FastInvoke on a MethodInfo no longer wraps an exception thrown by the method it invokes. On .NET 7 and later it invoked through reflection, which reports such an exception as a TargetInvocationException with the real one inside it; on .NET 6 it invoked through an emitted delegate, which reports the exception as it was thrown. The same call therefore reported different exceptions on different target frameworks. It now reports the exception as it was thrown on every one of them, which is what the .NET 6 path already did. Code which catches TargetInvocationException around a call to this method should catch the exception the invoked method actually throws instead.
