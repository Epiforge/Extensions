FastInvoke, FastGetValue and FastSetValue no longer wrap an exception thrown by the method, constructor, property getter or property setter they reach. On .NET 7 and later they went through reflection, which reports such an exception as a TargetInvocationException with the real one inside it; on .NET 6 they went through emitted delegates, which report the exception as it was thrown. The same call therefore reported different exceptions on different target frameworks. They now report the exception as it was thrown on every one of them, which is what the .NET 6 path already did. Code which catches TargetInvocationException around a call to any of them should catch the exception the invoked member actually throws instead.
