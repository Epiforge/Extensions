An expression containing a default value, such as the last branch of a chain of conditionals which a formula or rule engine emits for a switch with no default of its own, can now be observed, and is observed by subscribing directly to its change sources where the rest of the expression is eligible. Previously observing one threw NotSupportedException whether or not direct subscription was enabled.
A query reading the maximum or minimum of a concatenation, an element of one, or filtering one now enumerates it rather than reading it element by element through its indexer, which takes a lock on every read. The maximum of two thousand elements concatenated from two projections takes 3.7 μs where it took 46.0 μs, and from two lists 3.8 μs where it took 26.4 μs, at a cost of 131 to 184 bytes more each time such a query is constructed. A prepending or an appending now reports whether its source is costly to read by index, as a slice already did, so that what reads it chooses the same way.
IndexOf on a query which is costly to read by index, which includes a filter, a projection, a flattening, one delivered through a synchronization context and a concatenation, returned -1 whatever it was given; it now returns the element's position. On other queries it returned the right position, but looking for an element which was not there enumerated the whole query once for every element it held; it now reads each element once.
ObserveMax and ObserveMin now accept an IComparer<T>, with or without a selector, so that values can be compared under a culture or an ordering of the caller's choosing rather than the calling thread's culture; observations given the same comparer share one query. The maximum of a thousand names taken this way costs 314.7 μs and 887,344 bytes, against 966.5 μs and 1,619,472 bytes for the first element of a descending ordering, which was the way to do it before.
ObserveMaxBy and ObserveMinBy return the element with the greatest or least key, with or without a comparer of keys. Where several elements share the extreme key, which of them is returned is unspecified, and a comparer which breaks the tie makes it deterministic. A comparer is given only what the key selector produced and is consulted again only when something the selector reads announces a change.
ObserveElementAt now accepts a function which computes the index from the number of elements, evaluated in the same pass which reads the element, so that a median, a percentile or a quartile can be selected from an ordering without the index and the count ever disagreeing. The function is not called while the collection is empty, which faults as ObserveFirst does, and an index outside the collection faults as ObserveElementAt does.
ObserveRank counts, for an element, how many elements of the collection sort strictly ahead of it and how many sort level with it, itself included, under the same keys and directions ObserveOrderBy takes, and shares the ordering ObserveOrderBy maintains for them. A rank which shares places among ties, as Excel's RANK.EQ does, is one more than the number ahead; one which averages them, as RANK.AVG does, adds half of one more than the number level. Constructing one over an ordering already held costs 748 ns and 2,256 bytes. Keeping one current costs about 0.45 μs for each key change in the ordering, because every key change re-reads every rank over that ordering, whether or not it moved anything.
ObserveMax and ObserveMin now read a comparison by its sign. Previously they replaced the value they held only when a comparison returned exactly 1 or -1, so over a type whose comparison returned any other positive or negative number they reported whichever element they had met first.
Every collection query carries one more reference field, and every ordering a second, for the queries these operators cache; the caches themselves are created only when first used.
