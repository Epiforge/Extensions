`ObserveValueFor` and `ObserveValueForOrDefault` follow a change announced under a key the dictionary's comparer considers equal to the one observed, which is how a case-insensitive dictionary announces a change made through a differently cased key; they missed it before.
A query whose fault stands for the same reason through a change to its source keeps reporting the same fault and announces nothing, where it replaced the fault with a new one and announced it: an element or single element out of range, whatever kind of query it is taken from, the extreme or average of an empty sequence, the value for a missing key, the rank of an element not ordered, the faults of a projection over a collection, and the null and duplicate keys of a projection over a dictionary.
`ObserveWhere` announces the elements a range removal took out of it in the order they stood; it announced them in reverse.
An observer given a logger which does not write traces no longer composes the traces it would have written, so it allocates nothing more per change than an observer given no logger; it composed each trace, with an array for its arguments and a box for each value-type result, before the logger discarded it.
Filtering, projecting, flattening, ordering and synchronizing queries announce a change of one element without building lists to describe it, and bring the copies they keep up to date in place, without copying the elements an announcement carries.
Scalar queries announce a new result without allocating notification arguments for it; sums and averages take up a change without a cast sequence, and an average converts its count to its result type without boxing it.
Copying a collection query into an array or list, whether through `CopyTo`, `ToArray`, `ToList` or a list's constructor, stores each element directly rather than through `Array.SetValue`, so a copy of value-type elements no longer boxes each one, and a query over a source, a filter or a projection copies the elements it keeps in one block.
`ObserveToDictionary` gathers the keys a change touches in a set it keeps rather than one it allocates for every change.
`ObserveSelect` over a dictionary keeps its observations in a plain dictionary rather than an observable one, and finds which element a projected key falls to next without allocating.
Where an observation is evaluated by a graph of nodes, a node whose new value comes from a static method or operator no longer allocates when its value changes, asks whether a replaced value ought to be disposed of only when it can be, calls a method, constructor or indexer of three or four parameters without an array for the arguments, and reads an indexer without boxing its arguments.
`ObserveSelect` takes up an addition to its source without allocating a list of faults unless an added element's projection faults.
An observation evaluated directly holds less for each element a query observes: it keeps a lone subscription without an array around it and needs no lock for its single dependent, and a source it stops following is released with the handler registered rather than a new one, so an element added to and removed from a filter, projection or ordering allocates 128 bytes less on .NET 9 and later and 112 bytes less before.
An observation evaluated directly is consumed as itself rather than through a wrapper subscribed to it, so each element a query observes holds one object fewer and a subscription fewer, and a change to it is announced without passing through the wrapper; an element added to and removed from a filter, projection or ordering allocates 128 bytes less again.
An object only one direct subscription watches is registered with by that subscription alone, a shared registration being made only once a second subscription over the same object and event arrives, and without registering with the object again, so an element observed once holds 56 bytes less and a change to it reaches its observation one step sooner.
Building a query costs less where it finds nothing to hold: a list of faults gets its storage with its first fault, filters, projections, casts and flattenings make what they keep of their elements with the first element, a flattening stops allocating to walk what it releases, and a source query unsubscribes from its collection with the handler it subscribed rather than a new one, so a filter, projection or cast built and disposed over an empty source allocates 136 bytes less, a flattening 240 bytes less and a source query 56 bytes less.
`ObserveCast` keeps the cast of each element and nothing else per element, rather than observing each element through a projection whose result could never change, so a cast over a thousand elements built and disposed allocates 8 kilobytes rather than 462, an element added to and removed from a cast allocates 288 bytes rather than 600, and a replacement passing through a cast no longer observes the element it brings; what a cast reports, faults included, is unchanged.
`ObserveOfType` over a collection keeps which elements are of the type and those that are, and nothing else per element, rather than observing each element through a filter and a cast whose results could never change, so a type filter over a thousand elements built and disposed allocates 10 kilobytes rather than 415 and an element added to and removed from one allocates 288 bytes rather than 712; it raises its own `Count` notifications once its elements have changed, where it forwarded its source's before its elements had; what it reports is otherwise unchanged.
`ObserveCast` and `ObserveOfType` over a dictionary convert each value and keep nothing else per value, rather than observing each value through a projection, or a filter and a projection, whose results could never change, and size what they keep for their source, so a cast or a type filter over a thousand values built and disposed allocates 32 kilobytes rather than 964 or 935; they now announce changes to `Count` as a filter over a dictionary does, which they did not before, and a cast lists the faults of its values in an order of its own; what they report is otherwise unchanged.
`ExpressionObserverOptions` documents that an observer copies its options when it is instantiated, so that a change made to them afterward reaches only observers instantiated after it.
