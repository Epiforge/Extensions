Observable expressions and queries now work where the runtime cannot generate code, on both the graph and direct subscription: checked under Native AOT on macOS and Linux and under Mono's ahead-of-time compilation in the iOS simulator, where before nearly every observation threw PlatformNotSupportedException.
Direct subscription now compiles each observed lambda to a delegate of two parameters, which a runtime without code generation can make from an interpreted lambda; a delegate of more than two parameters needed a generated thunk there.
The package is marked as compatible with ahead-of-time compilation; where it rebuilds a part of a caller's expression, whatever that part needs from trimming or code generation the caller's own expression needed first.
Without code generation the library now evaluates the lambdas it would otherwise compile itself, on direct subscription and in the graph's operators, conversions, type tests and coalescing, rather than interpreting them; each primitive operation is the C# operator that compiles to the instruction a compiled lambda executes, so results, overflow and faults agree with a compiled lambda, and anything it does not cover is interpreted as before.
Without code generation an observation costs more than with it. Measured with dynamic code turned off: an evaluation on direct subscription costs 44.4 ns and 24 B, against 12.5 ns and nothing with it; a property change in a filtered view of a thousand costs 49.8 ns and 24 B on direct subscription, against 13.2 ns and nothing, and 569.1 ns and 72 B on the graph, against 35.7 ns and 24 B; building and disposing of that view costs 583 μs and 903 KB, against 290 μs and 856 KB. Under Native AOT an evaluation on direct subscription costs 38.4 ns and 24 B. With dynamic code, the two-parameter delegate costs what the five-parameter one did: every measure allocates what 7.0.4 did, and none differs from it in time by more than 2.3%.
