The wrapper each observation returns now attaches to the query it shares with other observations only for the notifications something has subscribed to it for, and only while something has. Every wrapper used to attach handlers for `PropertyChanged` and `PropertyChanging` when it was made, and a lookup's wrapper for both `DictionaryChanged` events too, so disposing many wrappers over one shared query removed each handler from a list as long as the number of wrappers still standing, at a cost in time and memory growing with the square of that number. Making and disposing 4,096 lookups over one shared lookup went from 106,886 μs and 346.77 MB to 336 μs and 416 KB, and 4,096 filters over one shared filter from 43,854 μs and 173.57 MB to 248 μs and 320 KB. The order in which they are disposed no longer matters.
Each wrapper now creates the lock guarding its subscriptions only when something first subscribes to it, so a wrapper nothing subscribes to is 40 bytes lighter than it was.
A wrapper which had been disposed still attached to its query when a handler was added to its `CollectionChanged` event, or to a dictionary wrapper's `DictionaryChanged` events, and then forwarded the live query's changes to that handler. A disposed wrapper now ignores a handler added to any of its events.
