A query or an observation built from several threads at once is now cached only once it is built, so no thread waits on one another thread is still building; a thread building a query or observing an expression while it holds a query's changes, as a selector does while its projection is built or while a change to its source is announced, could otherwise deadlock with a thread building the same query over a source it held, as two threads building over different groupings of one lookup did. Where two threads build the same query or observation at once, the one cached first is shared and the other is released, so a method an expression calls may run once more than it did. Building a query now takes 11 to 18 ns longer, which is 4% to 9% of building one over an empty source and leaves the seven queries Grindstone builds for a time slice within 4% of 7.1.3 over an empty source and within 1% over one element; observing a query already cached takes 8% less time, an observation built on the graph allocates 150 bytes less, 6% less for the one measured, and a query built over a source with an element allocates 16 bytes less.
