Observable expressions and queries now work where the runtime cannot generate code, on both the graph and direct subscription: checked under Native AOT on macOS and Linux and under Mono's ahead-of-time compilation in the iOS simulator, where before nearly every observation threw PlatformNotSupportedException.
Where the runtime cannot generate code and the library cannot evaluate an observed lambda itself, direct subscription hands it to the interpreter as a delegate of two parameters, which such a runtime can make from an interpreted lambda without a generated thunk; where the runtime can generate code, direct subscription compiles the same delegate 7.0.4 did.
The package is marked as compatible with ahead-of-time compilation; where it rebuilds a part of a caller's expression, whatever that part needs from trimming or code generation the caller's own expression needed first.
Without code generation the library now evaluates the lambdas it would otherwise compile itself, on direct subscription and in the graph's operators, conversions, type tests and coalescing, rather than interpreting them; each primitive operation is the C# operator that compiles to the instruction a compiled lambda executes, so results, overflow and faults agree with a compiled lambda, and anything it does not cover is interpreted as before.
Without code generation an observation costs more than with it. Measured with dynamic code turned off: an evaluation on direct subscription costs 44.3 ns and 24 B, against 12.3 ns and nothing with it; a property change in a filtered view of a thousand costs 50.1 ns and 24 B on direct subscription, against 13.4 ns and nothing, and 579.5 ns and 72 B on the graph, against 39.5 ns and 24 B; building and disposing of that view costs 605 μs and 903 KB, against 301 μs and 856 KB. With dynamic code, every measure allocates what 7.0.4 did, and repeated evaluation is within 2% of 7.0.4's time on x64 and on Apple Silicon.
